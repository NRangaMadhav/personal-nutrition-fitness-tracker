# Personal Nutrition & Fitness Tracker

A local-first nutrition tracker with a Streamlit UI, FastAPI backend, PostgreSQL, private MinIO image storage, and user-reviewed AI logging.

## Start the application

Prerequisites: Windows, Python 3.12, and a running PostgreSQL service.

From this project directory:

```powershell
.\run.ps1
```

If PowerShell blocks unsigned local scripts, use a process-only exception:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

- Application: http://localhost:8501
- API documentation: http://localhost:8000/docs
- Database health: http://localhost:8000/health
- Private MinIO API: http://127.0.0.1:9000

The launcher applies pending migrations, starts MinIO, FastAPI, and Streamlit, verifies readiness, then supervises its own processes. Keep its terminal open. Ctrl+C stops the processes it started, not your PostgreSQL service. It refuses to take over occupied ports. All services bind to loopback; this is not a public deployment.

The dedicated `.venv` uses Python 3.12.10 and does not share global packages. The launcher invokes that interpreter explicitly; activation is optional. Never run a global `pip install` for this project.

## First-time setup or restoring dependencies

```powershell
.\setup_local.ps1
```

On a new machine, the script creates `.venv` and copies `.env.example` if needed. Fill in the local `.env`, then rerun setup. Use dedicated database URLs with database names, not the PostgreSQL server URL alone.

Configuration:

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Dedicated application database, named `nutrition_tracker` in this local setup |
| `TEST_DATABASE_URL` | Separate test database whose name ends in `_test` |
| `JWT_SECRET_KEY` | Random signing secret, generated by bootstrap if empty |
| `NVIDIA_API_KEY`, `GROQ_API_KEY` | Server-side provider credentials |
| `NVIDIA_MODEL`, `NVIDIA_VISION_MODEL` | NVIDIA text and image model identifiers |
| `GROQ_MODEL`, `GROQ_VISION_MODEL` | Groq text and image model identifiers |
| `AI_PRIMARY_PROVIDER` | Default provider, initially NVIDIA |
| `OBJECT_STORAGE_ENDPOINT` | Local S3-compatible MinIO endpoint |
| `OBJECT_STORAGE_ACCESS_KEY`, `OBJECT_STORAGE_SECRET_KEY` | Random local credentials, generated if empty |
| `OBJECT_STORAGE_BUCKET` | Private image bucket |
| `BACKEND_URL` | FastAPI address used by the UI |

API models and availability are provider-controlled. Text and vision can use different models. If a configured model becomes unavailable, update the corresponding value and restart. Manual tracking does not require model credentials.

The supplied secrets are kept only in the ignored local `.env`. Rotate credentials that have been shared in a chat or any other external surface. Never commit `.env`, database exports, personal images, logs, or API tokens.

`requirements.txt` expresses direct dependency ranges; `requirements-lock.txt` records the compatible installed environment. Setup uses the lock file when present. Package installation disables an unrelated machine-wide extra package index for that process only; global Python/package settings are not changed.

MinIO's official Windows binary is downloaded into ignored `.local\bin`. Its persistent object data lives in `.local\objects`. MinIO is separately licensed software; its license is available via `minio.exe --version`.

## First use

1. Open the application and create your own account; there is no default password.
2. Complete your profile, including timezone and initial weight.
3. Review suggested daily targets or enter your own in Settings.
4. Use Dashboard's Add Log options for meals, water, weight, and supplements.
5. Review trends in History.
6. For AI Log, enter text, upload an image, or supply both. Review and correct the draft, then explicitly confirm.
7. Ask AI Coach about a selected date range. Inspect the calculated facts alongside its explanation.

Nutrition inputs describe the **total entered portion**, not values per 100 g. Model-derived nutrition is an estimate. Supplement logging uses one daily expected dose/status per configured supplement; taken, explicitly not taken, and unlogged are different states.

Target suggestions use a documented sedentary maintenance assumption, not an automatic weight-loss prescription. Profile sex and age may limit automatic recommendations; manual targets remain available. These features provide general wellness tracking, not diagnosis or individualized medical treatment.

## Data and AI guarantees

- Only FastAPI connects to PostgreSQL.
- Every protected operation is scoped to the authenticated user, including related record and image access.
- Current weight comes from weight records, not a separate independently editable profile value.
- Event timestamps are timezone-aware; history uses the profile's local day.
- Daily targets are effective-dated.
- Empty or untracked periods are reported as missing data rather than invented intake.
- BMI, totals, averages, adherence, and goal progress are deterministic backend calculations.
- AI drafts do not affect Dashboard, History, or Coach facts.
- Confirmation validates the edited batch and saves it transactionally; repeated confirmation cannot duplicate records.
- Coach is read-only and receives backend facts, not database credentials or unrestricted SQL access.
- Original images are private objects, not database binaries or public image URLs.
- AI receives an orientation-corrected JPEG copy capped at 1024 pixels on its longest side and 128 KiB before base64 encoding; the private original is unchanged. Transparent areas are rendered on white. Check small label text and estimated portions during review.
- Selected AI inputs/facts are sent to the selected external model provider. Never submit data you do not want that provider to process.

## Tests and schema management

Run from the project directory:

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m alembic check
.\.venv\Scripts\python.exe -m pip check
```

With the application running, an optional end-to-end check creates and removes its own synthetic account:

```powershell
.\.venv\Scripts\python.exe scripts\smoke_local.py
# Also contact real AI providers with synthetic examples (may incur provider charges):
.\.venv\Scripts\python.exe scripts\smoke_local.py --ai
```

Tests require the dedicated `TEST_DATABASE_URL`. Backend fixtures use PostgreSQL transactions and savepoints; they refuse to use a database not ending in `_test`. Provider and storage calls are mocked in routine tests, avoiding real API charges and personal-data transfer.

Schema changes:

```powershell
.\.venv\Scripts\python.exe -m alembic revision --autogenerate -m "describe the schema change"
# Review the generated migration before applying it.
.\.venv\Scripts\python.exe -m alembic upgrade head
```

Do not point tests at your application database. Do not edit existing applied migrations to change a live schema.

## Troubleshooting

- **Occupied port:** an existing tracker may already be running. Visit the URLs before starting another copy. Stop only the process you own; the launcher does not kill unrelated processes.
- **Database unavailable:** confirm PostgreSQL is running and the local URL names the dedicated database.
- **Login expires:** sign in again. Logout clears the current UI session; previously copied JWTs remain valid until their expiry.
- **AI request fails:** manual tracking remains available. Check provider/model configuration, network connectivity, account quota, and model modality support. Errors never become confirmed logs.
- **AI photo requests:** uploads use a bounded 30-second connection/write timeout and a 60-second response timeout. Large originals are compressed only for inference. Typed AI errors distinguish upload timeouts, provider access problems, and invalid output without displaying raw provider responses. Automatic fallback still requires a configured vision model; Groq's text model cannot analyze a photo.
- **Image upload fails:** check MinIO readiness, storage credentials, and supported image type/size.
- **Startup failure:** inspect `.local\backend.log`, `.local\streamlit.log`, and `.local\minio.log`. These files are local and ignored.
- **Changing environment values:** restart the launcher so all services load the new settings.

## Local persistence and deployment boundary

Accounts and confirmed logs persist in PostgreSQL. Images persist in `.local\objects`. Do not delete that directory to clear the UI: it would remove stored images. Protect backups of both PostgreSQL and the object directory, plus the local configuration required to restore access.

Public hosting, production account recovery, hardened production access controls, managed secrets, scheduled backups with restore drills, and operational monitoring are deliberately left for the later deployment phase. This setup is intended for local use only.
